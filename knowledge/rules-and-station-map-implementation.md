# Rules and Station Map Implementation

Checked 2026-10-24 against the local October 4 rulebook scans and the supplied `taibeled/JetLagHideAndSeek` source.

## Confirmed rules implemented

- Investigation questions are selectable whenever their printed scale permits. “Draw N, Pick M” is the hider's reward after answering; it does not randomly deal the seekers' question choices. Repeating a question remains allowed and repeats the card draw/pick as a separate reward set.
- Radar's printed `Choose` row now asks the seeker for a positive distance in meters. The authority freezes that radius on the question, calculates the answer from fresh player locations, and applies the map circle from that same radius; fixed Radar prompts reject custom radii. [Investigation Book scan, p. 3; `tests/engine/automatic-question-answer.test.ts`; `apps/mobile/tests/question-flow.test.ts`, checked 2026-10-24]
- Standard hiding periods are 30/60/180 minutes by small/medium/large scale. The hider's answer window is five minutes, with photo answer windows of ten minutes for small/medium and twenty minutes for large. The base rules do not add a cooldown after a resolved answer.
- “Draw 1, expand maximum hand size by 1” immediately draws and keeps one card, then increases the maximum by one for the rest of the round; the rulebook permits stacking it. It is now imported as a typed authoritative effect, applied by the engine, exposed to the hider projection, and reset on round transition. [rulebook scan, p. 46; `tests/engine/cards.test.ts`]
- Veto ends the active response with no answer or reward, while its question remains asked for future repeat cost. Randomize cancels its original question and starts a random unasked replacement in the same category; the original remains eligible at original cost. A null answer to the replacement is valid, resolves with no map constraint, and still qualifies for the hider reward. Both effects use public match events so all role-scoped phones transition consistently. [rulebook scan, p. 46; `tests/engine/cards.test.ts`, checked 2026-10-24]
- Thermometer uses printed minimum seeker travel distances of 1 km and 5 km at every scale, 15 km at medium/large, and 75 km at large; valid answers are hotter or colder. Automatic resolution requires fresh, accurate seeker and hider fixes, proves the printed minimum distance after accounting for GPS uncertainty, and compares the active hider's distance to the frozen seeker endpoints. The map resolver uses those same endpoints. [Investigation Book scan, p. 3; base rulebook scan, p. 17; `tests/engine/automatic-question-answer.test.ts`, checked 2026-10-24]
- Measuring answers are only closer or further. “Same” is not a legal answer; if location/feature precision cannot distinguish the result, the app should request better evidence or use the printed null-answer path where applicable. [base rulebook scan, pp. 22–23; `tests/engine/gameplay-rules.test.ts` and `tests/importer/importer.test.ts`, checked 2026-10-24]
- Every one of the 18 printed Photos prompts now has scan-derived, per-question instructions in both workbook import paths. The app uses the scan text instead of showing conflicting workbook requirement summaries; referee approval remains required for judging the submitted image. The scans correct several workbook differences: large street tracing is 1 km (not 1/2 mile), Park requires 2 m clearance (not 5 ft), Two Buildings asks for the bottom through four stories (not a 5 ft × 5 ft three-element patch), and the mountain image allows up to 3× zoom rather than requiring exactly 3×. General photo rules include normal phone aspect ratio, the valid absent-subject answer with reward, and the ban on Google Street View assessment. [base rulebook scan, printed pp. 32–35; Investigation Book, pp. 4–5; `tests/importer/importer.test.ts`; `apps/mobile/tests/question-guidance.test.ts`, checked 2026-10-24]
- Photo challenge attachments must be visible to seekers so they can judge whether an answer meets the printed specification. The evidence context now assigns these question attachments `public_match` scope; the engine projection test confirms the public, hider, and seeker match views receive the linked photo evidence while unrelated team chat stays private. [base rulebook scan, printed p. 32; `tests/engine/chat.test.ts`; `apps/mobile/tests/evidence-flow.test.ts`, checked 2026-10-24]
- All 24 standard curse cards now carry a separate rulebook clarification field with the printed source page. The card detail UI displays these alongside the workbook card effect, including definitions and edge cases for Bridge Troll, U-Turn, Urban Explorer, Lemon Phylactery, Water Weight, Jammed Door, Ransom Note, and the other physical challenges. This makes the adjudication instructions visible without claiming those real-world challenges are automatically verified. [base rulebook scan, printed pp. 48–57; `tests/importer/importer.test.ts`; `apps/mobile/tests/cards-guidance.test.ts`, checked 2026-10-24]
- Each player can explicitly grant background GPS permission for an active match. Expo Task Manager is defined at the router entry point; background fixes publish through the active location handler or queue locally under a match/recipient scope for recovery after a JS restart. iOS background mode and Android background/foreground-service permissions are configured. Web and native config/type checks do not prove OS delivery; physical iOS/Android behavior still needs field validation. [Expo SDK 55 Location docs, https://docs.expo.dev/versions/v55.0.0/sdk/location/ and Task Manager docs, https://docs.expo.dev/versions/v55.0.0/sdk/task-manager/, checked 2026-10-24]
- Match creation lists installed content packs, shows version and validation status, and pins the selected version through the authoritative match aggregate, snapshot, server record, and player projection. Multiple installed versions may share a pack ID; ambiguous creates are rejected, and player screens resolve questions, cards, and rule guidance using the exact match ID/version. Players can import validated JSON packs up to 5 MB; the catalog stores them locally and restores them on startup. A changed pack must use a new version, and each joining device must have that exact version installed because pack distribution is not yet online. Migration `202610250001_pin_match_content_pack_version.sql` backfills deployed rows from snapshots and changes pack-reference keys to ID/version pairs. Only the standard base-game pack is bundled; additional variants, applying the hosted migration, and cellular multi-version joins remain open. [packages/engine/src/commands/execute-command.ts; `apps/mobile/src/runtime/content-pack-catalog.ts`; `apps/mobile/src/runtime/mobile-runtime-orchestrator.ts`; `apps/mobile/tests/content-pack-catalog.test.ts`; `apps/mobile/tests/runtime-orchestrator.test.ts`; checked 2026-10-25]
- Hiding-zone radius is 500 m for small/medium and 1 km for large. The zone is centered on a selected transit station; the hider stays within the zone after the hide timer. Final hiding spots must be within 3 m of a marked path. Found requires visual identification and distance within 2 m.
- The scanned base rulebook describes Move's effect: pause the hider clock, freeze seekers and questions, move by valid transit to a new station-centered zone, discard the whole hand, reveal the original station, then resume; it cannot be used after endgame begins. The engine opens a Move window, blocks seeker movement/questions, immediately discards the hider's other hand cards, reveals the origin station to seekers without revealing the hider's location, permits hider-only relocation, requires a different in-boundary station and arrival before closing, enforces the sourced 10/20/60-minute scale timer, and excludes the window from survival scoring. The mobile map shows the remaining timer and requires a fresh device GPS fix within 100 m to confirm arrival. Duration provenance points to the community card transcription because the scan/workbook omit these values. [base rulebook scan, p. 26; https://jetlag.naenae.cat/, checked 2026-10-24]

## Map implementation state

- Discard 1 Draw 2 and Discard 2 Draw 3 now import as authoritative `discard_then_draw` effects with explicit discard/draw counts. The engine requires payment from other cards in hand before drawing replacements, and mobile marks the cards engine-supported. [base rulebook scan, p. 46; `tests/engine/gameplay-rules.test.ts`, checked 2026-10-24]
- Duplicate's scanned definition is imported with its exact copy rule and original-card preservation. At capture, every held Duplicate scores as a copy of the largest time bonus still held; the duplicate is retained in hand. During play, the hider selects an eligible hand card; supported typed power-up effects use the normal authority path, and manual challenges are identified privately in the resolution window. The original card is excluded from payment costs and is preserved in hand. [base rulebook scan, pp. 25–26; `tests/engine/cards.test.ts` and `tests/engine/hiding-zone.test.ts`, checked 2026-10-24]
- Station-name-length Matching now queries named railway stations, halts, tram stops, subway entrances, and public-transport stations from OSM. The authority compares normalized Unicode character counts for each player's nearest station, counting spaces and hyphens, and applies an approximate grid deduction using that same predicate. Unnamed station features are excluded. [base rulebook scan, p. 11; Investigation Book, p. 1; `tests/engine/automatic-question-answer.test.ts`, `tests/transport/online-runtime.test.ts`, checked 2026-10-24]
- Street-or-Path Matching now loads OSM highway ways with line geometry. Connected ways sharing the same name are treated as one segment; unnamed ways are split at mapped intersections. The authority measures each device fix to line geometry (including GPS-confidence margin), compares the nearest segment IDs, and samples the same segment predicate to narrow the map. Incomplete OSM geometry stays on the manual path. The provider identifies itself to Overpass with a project User-Agent and uses bounded, cached, on-demand queries. [base rulebook scan, p. 18; OpenStreetMap [highway tagging](https://wiki.openstreetmap.org/wiki/Key%3Ahighway); `tests/geo/openstreetmap-feature-provider.test.ts`, `tests/engine/automatic-question-answer.test.ts`, checked 2026-10-25]

- The mobile app can query candidate train, tram, and rail stations from Overpass using the selected region bounds. Results are filtered to the actual selected polygon, including holes, then deduplicated by OSM element ID and merged for same-name stops within 200 m.
- The map workbench can select a result and preview its geodesic scale-correct radius on web SVG and native map overlays. Requests are on demand, and the UI attributes station data to OpenStreetMap contributors.
- During the hide phase, the hider can set a station-centered zone. The command stores station ID/name/coordinates, selected time, selector, and the scale-specific radius in authoritative hidden state. The hider and referee can view it; seeker and public projections do not expose it.
- The engine checks a dense set of geodesic samples across the zone against the playable polygon and rejects a circle that crosses the outer boundary or a hole. This is sampled geometric validation, not a proof for arbitrarily narrow map features.
- The hider must separately confirm arrival at the selected station before the hide phase can advance. Once the hide timer reaches zero, an authoritative snapshot refresh transitions the match to seek phase; the map screen triggers this refresh when the hider and zone confirmations are present.
- After seek phase begins, authoritative hider location updates outside the stored radius are rejected; the engine also rejects hider movement updates during endgame. Ordinary question/card prep no longer fabricates a center point or skips hide phase; only explicit test/demo setup uses a clearly named demo station.
- During seek phase, the hider can mark a private final pin after attesting it is publicly accessible and within 3 m of a marked path. An in-zone seeker location update marked off transit automatically starts endgame and freezes the final pin. Endgame events and seeker projections omit the pin coordinates.
- Found confirmation requires a seeker/referee action, visual identification, and reported seeker coordinates within 2 m of the frozen pin. The round result records the hider team, finder, timestamp, and unpaused survival seconds; the live map presents a round scorecard.
- The mobile field-actions panel reads one GPS sample only when a player taps a location action. It uses that point to save the hider pin, report seeker transit status, or confirm a found. Separately, the live location-sharing provider publishes hider device fixes to authority storage and only exposes seeker tracks to hider views; seeker projections suppress hider coordinates. Background sharing remains an open platform workflow.
- Supported Matching and Measuring questions now load feature data on the authority from OpenStreetMap Overpass, scoped to the selected playable boundary and question feature class. The engine uses current seeker/hider fixes against that same returned snapshot, applies the map effect atomically, and records dataset source/version/retrieval time plus the reference feature. Feature data supplied by a player is ignored, and bulky feature lists are removed from persisted public event metadata.
- Tentacles now uses the printed rules from base rulebook pp. 36–37: candidate places are fixed from the asking seeker's radius, the hider must also be within that radius, and the answer is the closest reachable candidate to the hider. The authority computes supported classes from fresh device fixes and the same feature snapshot; if GPS uncertainty crosses the reach/nearest boundary it asks for a refresh, and an out-of-reach hider resolves with no map deduction. The map resolver now clips to the seeker's radius and the Voronoi region of the selected candidate set instead of rebuilding candidates around each hypothetical hider point. [tests/engine/automatic-question-answer.test.ts; tests/engine/constraint-resolution.test.ts]
- OpenStreetMap mappings cover selected classes such as airports, rail stations, aquariums, museums, libraries, hospitals, zoos, parks, golf courses, theme parks, cinemas, peaks, islands, station-name-length matching, administrative-division Matching, and administrative-border Measuring. Administrative relations are assembled into polygons; Matching compares first through fourth divisions only when the expected hierarchy is present and unambiguous at both fresh player locations, then narrows the map from the same boundary. Measuring uses only OSM ways shared by multiple divisions at the requested level and present in the playable region, then compares both fresh locations against the same nearest border and narrows the map from that distance. Incomplete hierarchy, missing shared ways, overlapping divisions, GPS uncertainty near the boundary, or unavailable data stay on the manual path. The ordinal mapping uses OSM admin-level bands (3–4, 5–6, 7–8, 9–10) as a limited approximation; OSM documents that these levels differ between countries, and OSM boundary completeness varies. The provider uses the shared public Overpass endpoint with a five-minute process-local cache; this is a prototype dependency, not a production service-level guarantee. [OpenStreetMap Wiki, [admin_level](https://wiki.openstreetmap.org/wiki/Admin_level), [boundary=administrative](https://wiki.openstreetmap.org/wiki/Tag%3Aboundary%3Dadministrative), checked 2026-10-25]
- Mobile question guidance now describes supported regional Matching/Measuring/Tentacles as automatic only while connected, and identifies unsupported feature classes as manual paths. Tentacles OSM mappings cover museums, libraries, movie theaters, hospitals, zoos, aquariums, and amusement parks; metro lines remain manual because representative-point OSM lookup is insufficient for the printed line question. Full suite verification for this slice is recorded in `tasks/todo.md` (2026-10-24).
- Matching templates now carry scan-derived notes for transit-line stops (including express trains that pass without stopping), station-name character counting, street/path segment endpoints, and the four administrative division levels. The picker and answer form show these separately from workbook requirements. The notes are concise paraphrases attributed to base rulebook printed pp. 18–19; they do not claim the automatic OSM answer/map path is implemented for these classes. [tests/importer/importer.test.ts; `apps/mobile/tests/question-guidance.test.ts`, checked 2026-10-24]
- All 20 Measuring templates now include the common answer/null-reward rule plus the scanned target definition: local/EU high-speed rail criteria, rail types, enclaves, administrative borders, altitude accuracy, named water, coastline width, map-icon distance, golf-course exclusions, and honorary-consulate exclusion. These are concise paraphrases attributed to base rulebook printed pp. 22–26 and shown in the same question/answer UI. [tests/importer/importer.test.ts; `apps/mobile/tests/question-guidance.test.ts`, checked 2026-10-24]
- During endgame, seekers can continue asking questions, the hider can answer, and the host can resolve map effects without leaving endgame. If a photo challenge cannot be completed from the frozen spot, the hider can record the book's “cannot answer” outcome; this bypass is restricted to photo challenges during endgame, and the hider can still draw the printed reward from the Deck screen.
- Standard-round rule gaps from earlier passes are now closed: held time bonuses score at capture, rounds rotate through the registered hiders with a deck reset, and the full single-device flow is covered by an integration walkthrough.
- Referee adjudication remains intentional for claims that cannot be inferred from map data: the selected OSM station identity, public access, marked-path proximity, truthful answers, visual identification, and photo evidence.
- The workbook import is still marked draft. The reconciled base-game pack has six categories, 80 printed question templates, one scan-attributed base ruleset, and a host-selected-boundary map preset; the importer reports 11 warnings and 5 informational findings, including four Thermometer values corrected to scan values. Radar `Choose` is implemented as a seeker-entered distance with automatic location answer and map radius. Veto, Randomize, Draw 1 Expand 1, Discard 1 Draw 2, Discard 2 Draw 3, and Duplicate's typed assisted description are present; remaining card issues still need adjudication. Runtime pack selection and map-preset selection remain open. It is treated as personal/private-use content while the source workbook's redistribution rights are reviewed; the scanned books stay local and are not bundled as full-page or full-text copies.
- A physical iOS/Android GPS walkthrough remains outstanding because this Mac has no Xcode `simctl`, Android `adb`/emulator, or connected phone. The full round is covered by the real runtime integration path and the mobile web screen was reviewed at phone width.
- The map workbench now saves and loads named scenarios locally, shares deflate-compressed app deep links, opens shared previews outside a match, restores boundary and hiding-zone overlays, and supports web drag/pinch plus zoom/reset controls. It follows the reference workflows inside the game UI rather than matching its Leaflet appearance or supporting its file picker, custom station sources, and arbitrary layer editor.
